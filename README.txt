HKC G27H7Pro 显示器控制（DDC/CI + Gamma）
==========================================
文件：
  MonitorSwitchTray.exe    托盘 + 弹出面板（推荐）
  Switch-DP1/HDMI1/HDMI2.exe  直接切输入源的小工具（适合绑热键/快捷方式）
  source\                  全部 C# 源码 + 两个编译脚本（用系统自带 csc.exe，无需 SDK）
  README.txt               本文件

界面参考了开源项目 MonitorBar（github.com/Binaryify/MonitorBar）的信息架构：
概览 / 画面 / 分辨率 / 屏幕时间 四个分页 + 顶部一张状态卡。

怎么用
------
* 左键单击右下角托盘图标（显示器+绿色箭头）→ 弹出控制面板
* 右键单击 → 传统菜单（打开面板 / 刷新 / 开机自启 / 退出 / 输入源 / 亮度…）
* 点面板外面或按 Esc 关闭面板

面板内容
--------
概览
  HDR 状态卡 ── 大字显示"○ HDR 已关闭 / ● HDR 已开启"，并用一句话说明
                亮度 / 对比度 / 色温 / 软件调光 现在能不能用；旁边一键切换 HDR（Win+Alt+B）
  输入源 ── DisplayPort-1 / HDMI-1 / HDMI-2 三个按钮，当前那个高亮
  亮度 ── 硬件背光滑杆（DDC/CI 0x10），拖动后自动写入并回读确认
  对比度 ── 同上（0x12）
  色温预设 ── 7500K / 9300K / 用户1（0x14）；右上角显示"当前：6500K"，能写的那一档会高亮；
              6500K 固件拒绝写入，需要在 OSD 里选
  右上角 ── "⚙ 设置"（全局快捷键）、"✕"关闭；左下角"开机自启动"是亮绿色开关按钮
画面
  软件调光 ── 用显卡 Gamma 表压暗画面（任何接口都能用，不动背光）
  色温 / 减蓝光 ── Gamma 色阶，3000K–6500K
  场景 ── 日间 / 阅读 / 观影 / 夜间 一键组合（亮度+对比度+调光+色温），当前生效的那个高亮、
              右上角写"当前：阅读"；手动动过任何一项就变成"当前：未套用预设"；另有"恢复默认"
分辨率
  当前模式 + 可用模式列表（双击应用），刷新率一起切换
屏幕时间
  今日使用/亮屏时长 + 最近 7 天柱状图（程序运行时每 60 秒采样，存
  %APPDATA%\MonitorSwitch\usage.csv）
底部：开机自启动（亮绿按钮，开=绿底"开机自启动 ✓"）、退出按钮、状态行（每次操作的结果都写在这里）
顶部行为：左键点托盘图标 → 打开面板；再点一次 → 关闭面板（开着时点图标即关闭）

分辨率页（参考 MonitorBar 的"分辨率"页）
----------------------------------------
· 刷新率：4 个常用档（160 / 144 / 120 / 60 Hz）做成一排按钮，按当前分辨率实际支持的显示；
  点一下 = 用当前分辨率换刷新率。右上角显示当前分辨率。
· 分辨率：只列常用 5 档（3840×2160 / 2560×1440 / 1920×1080 / 1600×900 / 1280×720），
  每行右侧是该分辨率能用的最高常用刷新率；当前档绿底 + "当前"。点一下 = 换分辨率（刷新率沿用当前的，
  不支持就取该分辨率下最高的一档）。
· 常用组合：3840×2160 / 2560×1440 / 1920×1080 三行，点一下 = 分辨率 + 刷新率一起切（都取 160 Hz）。
  这三行就是"整合了分辨率和刷新率的常用选项"。
· 概览页顶部"当前显示"大卡直接显示当前"分辨率 × 刷新率"（大字）+ 刷新率/色深 + 4K/2K/FHD 归类；
  面板顶部副标题也一直显示 "HKC G27H7Pro · 3840 × 2160 · 160 Hz"。
· 命令行也可以切：MonitorSwitchTray.exe --set-mode 2560 1440 160
· 实测：3840×2160 @160 ↔ 2560×1440 @160 双向切换成功（切换后自动把面板挪回可见区域）。

修（用户反馈：场景选中态不刷新）
--------------------------------
· 根因：自绘滑杆在"程序设值"时也触发了 Scroll 事件（原生 TrackBar 只在用户拖动时触发），
  于是"应用场景"里程序去设调光/色温滑杆的值时，事件把刚设好的 currentScene 又重置成 -1 ——
  表现为点了场景后按钮不高亮、状态文字不更新。
  修法：滑杆加 fromUser 标志，只有用户拖动才抛 Scroll。
· 顺带补：应用场景后概览页的硬件亮度/对比度数值与滑杆位置同步更新（原来只写了硬件、界面不动）。
· 实测：点"日间" → 按钮绿底高亮、"当前：日间"、底部"场景已切换到：日间"、调光 100% / 色温 6500K、
  硬件亮度读回 80；点"恢复默认" → "当前：未套用预设"、四个按钮全部取消高亮、硬件回到亮度 70 / 对比度 50。

修（用户反馈第 2 批）
--------------------------------
1. 场景与"色温预设"的关系讲清楚了：场景调的是**软件色温（显卡 Gamma）**，色温预设那 3 个按钮是
   **显示器硬件 DDC 0x14**（固件只接受 7500K/9300K/用户1），两层不是一回事、按钮不会跟着场景跳。
   现在色温预设卡里加了一行会动的字：「软件色温（Gamma）3600K · 夜间 场景」，
   套用场景时变绿，手动调整/恢复默认后变灰并显示"自定义/默认"。
2. 页签切换改成瞬间：① 切页签不再每次都跑一遍 DDC 读取（沿用上次读数，超过 2 秒才重新读）；
   ② 4 个页面/卡片容器全部双缓冲，消除页面互相切换时的重绘闪烁；
   ③ DisplayModes.List() 加 3 秒缓存（原来每画一行分辨率都要枚举 200 多个模式）。
   实测：点击页签后 200 毫秒截图，页面已经完全渲染。
3. 去掉"亮度/对比度/色温预设"三张卡片标题下面那行无用小字（DDC/CI 0x10、0x12、0x14），
   卡片高度相应收紧，概览页更紧凑。

★ 全局快捷键（在别的输入源上也能切回本机）★
---------------------------------------------
默认：Ctrl+Shift+1 = 回到 DisplayPort-1（本机）｜ Ctrl+Shift+2 = HDMI-1 ｜ Ctrl+Shift+3 = HDMI-2
默认组合键是实测挑过空闲的：这台机器上 Ctrl+Alt+1、Ctrl+Win+1..3、Alt+Win+1..3 已被别的程序占用。
显示器切到别的设备（本机画面看不见）时，直接按 Ctrl+Shift+1 就能切回这台电脑 —— 已实测。
改键：面板右上角"⚙ 设置" → 点某一行的组合键按钮 → 按新的组合（至少含 Ctrl/Alt/Shift/Win 之一，Esc 取消）。
设置存 %APPDATA%\MonitorSwitch\settings.ini；设置窗口底部会如实显示"已生效：…"或
"这些组合被别的程序占用了：…"（注意：同时开两个实例时，第二个实例会显示被第一个占用，这属正常）。

★★ 最重要的一条：HDR 开着时，亮度/对比度/色温/软件调光全都无效 ★★
--------------------------------------------------------------
这台 HKC 进入 HDR 模式后，画面通路交给 HDR 信号，面板锁在最大亮度、由系统做 tone mapping。
此时 VCP 0x10/0x12/0x14 的写入会被固件"收下并存进寄存器"（回读一切正常），但完全不作用到
面板；软件 Gamma 调光同样不生效。实测：HDR 开时把亮度从 70 写到 25 屏幕毫无变化；关掉 HDR
后同样的操作肉眼立即可见（100↔25 来回 4 次，使用者确认）。

程序的应对：
  * 面板顶部状态卡大字显示 HDR 开关状态 + 可用性说明（本次重点）
  * HDR 开时，亮度/对比度/色温/软件调光 的控件全部置灰
  * 点击被禁用/被拦的操作时弹出说明："HDR 开启中，这项不会生效；请先关闭 HDR"
  * 面板和右键菜单都有"切换 HDR（Win+Alt+B）"
  * 命令行：--hdr 查状态、--toggle-hdr 切换
HDR 状态读的是 HKLM\SYSTEM\CurrentControlSet\Control\GraphicsDrivers\MonitorDataStore\
<显示器>\HDREnabled（注意 AdvancedColorEnabled 不是 HDR 标志位）。

这台显示器实际可用的功能（2026-10-16 实测，HDR 关闭状态下）
----------------------------------------------------------
VCP     功能                实测结果
0x10    亮度 0-100          写 100/25/72/65 全部生效，100↔25 肉眼明显 ✔
0x12    对比度 0-100        写 100/20 来回 4 次，黑位/层次明显 ✔
0x14    色温预设            可写 0x06(7500K)/0x08(9300K)/0x0B(用户1)，色调变化可见 ✔；
                            0x05(6500K) 被固件拒绝（等 20 秒也不生效）；
                            0x01-0x04/0x07/0x0A 会让它变成"未设置"(0x00)；
                            且读回值会滞后/错位
0x16/18/1A  红/绿/蓝增益    读 50/50/50，写 52 生效并回读 ✔
0x60    输入源              DP1(0x0F) / HDMI1(0x11) / HDMI2(0x12) ✔
        ⚠ 坑：这台对 0x60 上报的 max 是 3（垃圾值）。程序里**不能**拿 max 去夹取目标值，
          否则 0x11 会被夹成 3，显示器直接忽略 → 表现为"切输入源没反应"（已修）。
0x62    音量                能读（70/100），这台没内置喇叭
0x8D    静音                能读（2）
0xC0    累计点亮时长        能读：3676 小时
0xC9/0xB6/0xC8/0xDF/0x02    固件/面板/控制器/VCP 版本等，只读
0xD6    电源模式            能读（1/4），未测试写入
不支持：水平/垂直位置、自动调整、缩放、HDR 开关（走 Win+Alt+B）、响应时间/Overdrive、锐度
        —— 不在显示器上报的能力列表里，只能在 OSD 里调。

软件调光（Gamma）的真实限制
----------------------------
实测 Windows/驱动对 Gamma 曲线有硬性约束：**每个通道的最亮点必须 ≥ 32768（即 50%）**，
且曲线单调不减、相邻差 < 32768。所以：
  * 单纯调光：只能到 51%（50% 会被拒）
  * 色温 3500K：能达到的最暗只有约 91%（蓝通道被压到 50% 就到底了）
  * 色温越暖，能压得越浅 —— 暖色和深调光互相挤占
程序的做法：触到下限时按同一比例抬高三个通道（色温比例保持不变），状态行会如实写出
"（系统下限：实际只能到 xx%）"。验证记录：14 组（调光 50-100% × 色温 3000-6500K）组合
在修正后全部被系统接受，修正前 50%/3500K+60% 等组合被拒。
退出程序或点"恢复默认"会写回标准曲线，不会把你的屏幕留在异常状态。

命令行用法（MonitorSwitchTray.exe）
-----------------------------------
  --panel                 打开面板（不带托盘图标）
  --panel-demo [秒]       面板摆在固定位置，默认 14 秒后自动退出（用于截图/自检，不碰鼠标）
  --check                 查询当前输入源
  --switch DP1|HDMI1|HDMI2 切换输入源
  --hdr / --toggle-hdr    查询 / 切换 HDR（等于 Win+Alt+B）
  --get <项>              读 VCP：brightness contrast color redgain greengain bluegain
                          volume mute usagetime power input
  --set <项>=<值>         写 VCP（自动回读确认 + 重试）；色温用 --set color=7500
  --modes                 列出所有显示模式
  --usage                 列出每日亮屏/使用时长
  --gamma-test            跑 Gamma 能力矩阵（哪些组合系统会接受）
  --gamma-reset           把 Gamma 恢复标准曲线
  --demo-menu             把右键菜单弹出来（截图自检）
Switch-*.exe 另有 -c（只查）和 -d（调试回读）
退出码：0 = 成功，1 = 失败；输出为 UTF-8，可重定向。

与 MonitorBar 的对照
--------------------
采用它的：面板式 UI、概览/画面/分辨率/屏幕时间的分页、DDC/CI 硬件背光、Gamma 软件调光与
色温、场景、分辨率切换、屏幕时间统计、"不支持的功能不显示"。
不适用本机的：局域网遥控（那是小米澎湃 OS 显示器专用）、跟随 MacBook 内屏亮度（无内屏）、
自动更新（自编译版本不走它的更新通道）。
比它多的：HDR 状态卡与可用性拦截、按实测固件行为裁剪过的色温档位、Gamma 下限的如实提示。

注意事项
--------
1. 显示器 OSD 里的 DDC/CI 必须保持开启，否则所有写入都会失败。
2. ★ HDR 开着时亮度/对比度/色温/软件调光一律无效（见文首）。
3. 切到没有信号的接口会黑屏显示 No Signal，DDC/CI 依然有效，可以切回来。
4. 切到没接设备的接口后，显示器可能过几秒自动跳回有信号的接口（实测 HDMI-2 约 7 秒回跳，
   HDMI-1 观察 26 秒未回跳）。这是显示器的"自动选择输入源"，不是工具故障。
5. 系统自带的亮度滑块对外接屏无效（WmiMonitorBrightness 枚举不到这台），只能走 DDC/CI。
6. 色温 6500K 想调回去要在 OSD 里选一次，DDC 写不进去。
7. 屏幕时间的"亮屏"是程序运行时长、"使用中"是最近 2 分钟内有键鼠输入（推断值，非精确）。
